# 스터디 주간 조회와 화면 연결

Issue60. 승인된 스터디 화면을 실제 기록에 연결한다. 홈 요약·개인 대시보드·관리자·
공식 공휴일은 다음 범위다. 새 DB 테이블·RPC·운영 데이터 변경은 없다.

## 조회와 권한

- GET /api/study?week=YYYY-MM-DD. 실제 월요일·2000년 경계·현재 서울 주간 이하만 허용한다.
  중복 조건·다른 조건·불가능한 날짜는400이다. weekStart/totalMinutes/activeMembers/members를 반환한다.
- 기존 records HTTP의 정상 사용자 세션·PIN 제한·no-store·오류 원문 차단·Server-Timing을 재사용한다.
  일반 쿠키가 없는 관리자와 제한 세션은 기록 조회에 진입하지 못한다.
- 달력 DB의 멤버·기록 검증과 ID 커서 페이지 조회를 readPeriod로 공통화한다. 같은 요청에서
  공개 멤버를 한 번만 읽고 회원 자격을 확인한다. 그룹·기간·회원 ID가 맞지 않으면503이다.
  메모·시작 시각·인증 정보 없이 필요한 ID/날짜/시간만 읽는다.
- calendarDays를 재사용해 항상 월~일7개 날짜, 가입순 전체 회원, 기록 없는 회원0일을 반환한다.
  같은 날짜의 여러 기록은 시간만 합산하고 공부일은 중복 계산하지 않는다.
  API 행 상한보다 적게 반환되더라도 빈 페이지까지 조회해 합계를 자르지 않는다.

## 화면과 팝업

- /study와 하단 스터디 메뉴를 활성화한다. 기존 StudyShell/PeriodPicker/notebook CSS와
  이모지 색상 토큰을 재사용한다. 가입순 카드·공부일·7칸 막대, 월~일 라벨을 유지한다.
- user/group/week별 메모리 Query 캐시, staleTime0·포커스/재접속·수동 갱신.
  기간 변경 시 이전 주 데이터를 새 주처럼 표시하지 않는다. 동일 기간 네트워크 오류는
  이전 자료를 유지하지만 세션/계정 오류는 숨긴다. 서울 주가 바뀌면 현재 주 선택을 갱신한다.
- 하단+는 기존 RecordForm의 서울 오늘 기본값·저장 재시도·초안 보호를 재사용한다.
  성공하면 스터디로 돌아와 집계를 갱신하고 토스트를 표시한다.
- 달력에서 검증한 뒤로가기 보호를 usePopupHistory로 공유한다. 폼 확인 전 렌더링을 바꾸지 않고
  취소는 초안 유지, 승인은 이력 이동, 제출 중은 이탈을 차단한다. compose=1 직접 주소도 처리한다.
- 대표 이모지 변경은 현재 사용자 카드에 즉시 반영한다. 가상 시안 데이터를 운영에 가져오지 않는다.

실기기 동기화는 미검증이다.
