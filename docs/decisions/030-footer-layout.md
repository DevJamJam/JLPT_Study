# 본문과 하단 메뉴 영역 분리

Issue62. 기존 fixed 하단 메뉴는 본문 위에 겹쳐 그려졌다. 마지막 여백만으로는 스크롤
중간의 카드를 보호하지 못한다. 이전 PR의 “겹침 없음” 검토는 이 문제를 놓쳤으며 정정한다.

- StudyShell을 화면 높이의 세 행(64px 헤더 / 남은 본문 / 하단 메뉴)으로 나눈다.
  본문에 min-height:0과 overflow-y:auto를 적용하고 바깥 페이지는 스크롤하지 않는다.
- 하단 메뉴는 본문 밖의 실제 행을 차지한다. 가운데+가 올라오는 높이도 별도 여백으로
  확보하고 safe-area 하단 패딩을 유지한다. 본문 끝 여백에 의존해 겹침을 감추지 않는다.
- 팝업 동안 본문 스크롤을 잠그고, 닫을 때 본문 위치와 포커스를 복원한다.
- 얇은 스크롤바의 좌우 공간을 대칭으로 확보해 본문이 한쪽으로 치우치거나 팝업 잠금 시
  가로로 움직이지 않게 한다. 본문 중앙 좌표도 화면 중앙과 비교한다.
- 디자인 검토 도구도 별도 행으로 감싸 /preview의 헤더·메뉴가 화면 밖으로 밀리지 않게 한다.
- 기존 기능 회귀와 별도로 본문·메뉴·+ 아이콘의 실제 좌표를 비교한다. 스터디·달력·내 기록의
  처음/중간/끝을 화면 크기 그대로 캡처한다. 마지막 카드/수정 버튼의 실제 접근성과 팝업 복귀
  위치를 검사한다. 전체 페이지 캡처만으로 시각 검토를 대신하지 않는다.

단위101개·브라우저138개·DB통합7개가 검증 대상이다. 실제 실행 결과와 수정 캡처는 PR에
기록한다. 실제 iPhone Safari와 기기별 safe-area는 미검증이며 Chromium 세 화면 크기와 구분한다.
