# 로그인한 사용자의 PIN 변경 (#37)

2026-10-23. 상단 이모지 → 내 설정 → 간편 비밀번호 변경을 연결한다. 별도 설정 페이지·중첩 팝업 없이 StudyDialog, Button, 토큰과 CSS Modules를 재사용한다. 이모지 저장·관리자 기능·기록/통계 연결은 후속이다.

- 기존 강제 변경 폼을 PinChangeForm으로 공유하고 normal 모드에서만 현재 PIN 입력을 추가한다. ASCII4자리·새 PIN 일치·실패 입력 유지·pending 중 중복 제출/닫기 방지·재로그인 안내를 공유한다. PIN은 웹 스토리지에 저장하지 않으며 팝업을 닫으면 메모리 입력도 제거된다.
- POST /api/auth/change-pin은 기존 Origin·JSON·크기 검사, Vercel 신뢰 출처, HttpOnly 쿠키, no-store·공개 DTO 원칙을 공유한다. 관리자 쿠키나 요청 사용자 ID를 받지 않는다. 제한 세션은403 PIN_CHANGE_REQUIRED로 차단한다.
- changePin 서비스는 일반/강제 변경을 함께 처리한다. 일반 변경은 reserveUserAttempt(change_pin) 이후 현재 PIN을 scrypt로 확인한다. 틀리면400 CURRENT_PIN_INVALID와 실패 예산을 기록하며 정상 세션 쿠키를 지우지 않는다. 같은 새 PIN은400 PIN_UNCHANGED,429는 해시·DB 변경 전에 반환한다. 지연 완료된 예약은401로 거부한다.
- DB의 기존 완결 트랜잭션을 replace_user_pin으로 공유한다. complete_pin_reset과 change_user_pin은 각각 제한/정상 모드를 고정한 얇은 래퍼다. 기존 RPC 계약과 강제 변경 검사는 유지한다. 그룹→멤버→자격증명→현재 세션 잠금, 현재/기대 버전·만료·모드 재검사, 버전 증가·모든 이전 세션 폐기·현재 정상30일 세션 발급을 한 트랜잭션으로 처리한다. 충돌 시 전체 롤백한다. SECURITY INVOKER·빈 search_path이며 세 함수 모두 service_role만 실행한다.
- 응답이 유실됐을 때 자동 재전송하지 않는다. 변경 전 토큰은 재사용할 수 없으므로401은 쿠키를 제거하고 새 PIN으로 재로그인하도록 안내한다. DB 오류 원문이나 해시·PIN·세션 원문을 JSON에 반환하지 않는다.

## 검증과 수정

단위61개 통과. 운영 빌드를 포함한 브라우저54개 통과. 새9개 검사는 입력 불일치·현재 PIN 오류 후 입력 유지·pending 중 닫기/Escape 차단·성공 Toast·재진입 시 빈 입력·세션 만료·초기화 세션의 설정 진입 차단·포커스 복귀를375×667/820×1180/1280×900에서 확인한다. 브라우저의 데이터 API는 대체 응답이며 실제 운영 DB 통합 검사와 구분한다.

초기 브라우저 검사에서 성공 Toast가 닫히는 dialog에 붙어 사라지는 문제를 발견했다. dialog 제거 후 effect에서 기존 toast 함수를 호출하도록 수정하고 전체54개를 다시 통과했다. 브라우저 설치 압축 해제의 chown 오류는 임시 환경에서 소유권 변경 없이 압축을 풀어 해결했다. 레포 의존성은 추가하지 않았다. CLI가 만든 중복 빈 migration은 제거하고 실제 SQL 파일1개만 유지했다.

새 SQL 계약은 제한 세션 차단·정상 변경·버전/만료/재전송 차단·새 세션 충돌 롤백·다른 사용자 보존·익명 실행 차단을 검사한다. 기존 강제 변경 계약도 함께 실행한다. 별도 PostgreSQL 연결의 동시 일반 변경은 두 번째 요청 UNAUTHORIZED·버전2·세션1개를 검사한다. 원격 CI/운영 적용·배포·통합 검증의 실제 결과는 PR에 기록한다.

Supabase 공식 변경 이력과 Database Functions 문서를 확인했다. 17.11의 ltree/pgcrypto/btree_gist 변경과 예정 TLS cipher 제거는 이번 SQL·Node 서버 요청 방식 변경을 요구하지 않는다. 공개 클라이언트 키 접근을 추가하지 않는다. 운영 브라우저의 프록시 인증서 오류는 해결됐다고 주장하지 않는다.
