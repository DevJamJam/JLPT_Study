# 가입·로그인 화면 연결 (#33)

2026-10-23. /login·/join을 실제 인증 API에 연결한다. 기존 공통 Button, 색상 토큰, PROFILE_EMOJIS, 닉네임·PIN 검증을 재사용한다. CSS Modules로 스타일을 분리하고 응답 타입은 features/auth/types.ts를 서버와 클라이언트가 함께 사용한다.

- /는 me로 실제 세션을 확인한다. 무세션401은 /login으로 이동한다. 정상 세션은 실제 닉네임·이모지·그룹을 표시하고 현재 세션 로그아웃을 제공한다. 기록·통계 가상 데이터를 표시하지 않는다. 제한 세션은 일반 홈 대신 PIN 변경 필요 상태만 보여준다.
- 로그인·가입은 JSON POST, same-origin 쿠키, no-store, 15초 요청 제한을 사용한다. PIN·세션·프로필은 웹 스토리지에 저장하지 않는다. 제출 중 fieldset 비활성화와 ref 잠금으로 중복 제출을 막는다.
- 가입 실패 시 입력과 requestId를 유지한다. 정규화된 닉네임·PIN·이모지가 바뀌면 새 UUID를 만든다. PIN 확인과 공동 공개 안내 확인이 필요하다. 대표 이모지는 고정20개 네이티브 라디오로 선택한다.
- 인증 오류는 고정된 한국어 안내로 표시한다. 429는 재시도 시각·관리자 문의를 안내한다. 연결 실패 시 자동 재전송하지 않는다. 로그아웃 실패는 현재 화면을 유지한다.
- 입력은16px·44px 이상이다. 가입 폼은 모바일에서 세로 스크롤하며 가로 넘침이 없다. 공통 디자인 미리보기는 /preview에서 별도로 유지한다.

## 실제 검증

npm run check·build, 단위54개, 기존 전체 브라우저 검사36개와 추가 인증 제한 검사3개가 통과했다(총39개). 새 인증 UI 검사는 API 응답만 대체하고 실제 브라우저·앱 라우트·폼·fetch를 실행한다. 세 화면 크기375×667·820×1180·1280×900에서 로그인/가입 캡처를 생성했다.

운영 API는 임시 계정으로 가입201→동일 요청200→내용 충돌409→로그인200→me200→로그아웃200→기존 세션 me401을 실제 확인했다. 사용한 임시 계정1개는 생성 요청 UUID와 닉네임을 함께 대조해 삭제했다. 운영 UI의 실제 폼부터 DB까지 통합 검증은 병합 후 별도로 확인한다.

검사 환경 문제: 이전 시도의0바이트 /tmp/chromium 때문에 실행이 즉시 종료됐다. 해당 빈 파일을 분리하고 별도 임시 경로에 설치한 Chromium 패키지의 실제 실행 파일을 풀어 해결했다. 한글·컬러 이모지 폰트를 검사 환경에 설치했다. 컬러 폰트의 이전 다운로드 경로는404였으며 공식 README의 2D/fonts 경로로 확인·수정했다. 앱 의존성·배포 자산에는 검사 전용 브라우저/폰트를 추가하지 않았다. 오류 선택자는 Next 페이지 이동 알림과 충돌해 form 내부로 한정했다.
