# 내 설정 대표 이모티콘 저장 (#39)

2026-10-24. 기존 설정 팝업에 대표 이모티콘20개 선택·저장을 연결한다. 가입 화면의 라디오 UI를 EmojiPicker로 분리해 재사용하고, PROFILE_EMOJIS와 isProfileEmoji를 가입/서버 검증에 공유한다. CSS Modules와 기존 색상·44px 입력 규칙을 유지한다.

- PATCH /api/me/emoji는 기존 createAuthHttp의 Origin·JSON·본문 크기 검사, 사용자 쿠키 해시 추출, no-store 응답과 오류 정제를 공유한다. 사용자 ID·닉네임 body는 권한 근거로 사용하지 않으며 관리자 쿠키는 허용하지 않는다. 공개 profile만 반환하고 쿠키·세션 만료를 변경하지 않는다.
- update_profile_emoji는 쿠키 해시에서 주체/그룹을 도출하고 그룹→멤버→자격증명→세션 순서로 잠근 뒤 기존 resolve_user_session(false)로 만료·현재 버전·정상 모드를 다시 검사한다. users.emoji의 기존20개 CHECK를 최종 선택지 제약으로 공유한다. 자기 users 행만 갱신한다. SECURITY INVOKER·빈 search_path·service_role 전용 실행이며 테이블 권한을 확대하지 않는다.
- 프로필 DTO 검증은 어댑터의 publicProfile 함수로 기존 세션 조회와 공유한다. 브라우저 fetch·JSON/오류 처리도 기존 authRequest와 같은 내부 함수로 공유한다. 이모지 저장은 PIN 해시나 인증 예산을 소비하지 않는다.
- ProfileSettings가 이모지 선택·PIN 전환·설정 취소·저장/로그아웃 상태를 담당한다. 실패하면 선택을 유지하고, 같은 값이면 저장을 비활성화한다. 성공 후 공개 프로필을 현재 화면에 반영하고 팝업 제거 뒤 기존 Toast를 표시한다. 다른 기기에서도 me 재조회 시 현재 users.emoji를 반환하며 과거 기록에 별도 이모지를 복제하지 않는다. push 동기화는 추가하지 않는다.
- 저장/확인 중 중복 제출·닫기/Escape·다른 작업을 막는다. 변경된 이모지를 남긴 채 닫기·PIN 전환·로그아웃 시 공통 confirmDiscard를 사용한다. native dialog 위에 확인창을 중첩하지 않도록 공통 확인 함수가 dialog를 잠시 닫았다 복원한다. 취소 시 선택과 포커스를 유지한다. 기존 preview의 확인 동작도 브라우저 검사로 확인한다.
- 만료/초기화된 세션은 재로그인 링크를 표시하고 추가 저장을 막는다. 응답 유실 후 같은 이모지를 다시 저장하는 것은 동일 users 행을 같은 값으로 갱신하므로 중복 기록·세션 생성이 없다.

## 실제 검증

단위64개 통과. HTTP 검사는 PATCH·공개 DTO·body의 타인 ID 무시·세션 쿠키 보존, 무세션/관리자 쿠키/선택지 오류/Origin 오류, DB 만료·초기화·무효/내부 오류와 잘못된 응답을 검사한다. 브라우저63개 통과(375×667·820×1180·1280×900). 새9개는20개 선택지·실패 선택 유지·저장/새 조회 후 갱신·진행 중 닫기/Escape·확인 취소/버리기·PIN 전환·로그아웃 취소·포커스 복귀·세션 만료 안내를 검사한다. 데이터 API는 대체 응답이며 실제 렌더링과 폼·fetch를 실행한다. 로컬 캡처에서 간격·색상·선택 표시·글자 겹침을 확인한다.

새 DB 계약은 본인 변경/재전송·다른 사용자 보존·credential/세션 만료 불변·잘못된 값·무세션·만료/버전 불일치·멤버십 제거·제한 세션·익명 실행 차단을 검사하고 롤백한다. PostgreSQL 동시 요청은 먼저 PIN을 변경한 뒤 이전 세션으로 대기하던 이모지 저장이 UNAUTHORIZED로 거부되고 이모지는 바뀌지 않는지 검사한다. 원격 CI·운영 DB 적용·배포·운영 API 검증 결과는 PR에 기록한다.

Supabase 변경 이력·Database Functions 공식 문서를 확인했다. 기존 환경의 예정 TLS cipher/17.11 확장 관련 변경을 이번 기능에서 변경할 필요는 없다. 이번 읽기 전용 점검에서 운영 로그인 페이지는200(약5.4초)였지만, 이전 가입 응답 시간 초과의 원인은 확정하지 않았다. 운영 전체 인증 흐름·실제 iPhone Safari 검증 성공으로 확대해 보고하지 않는다. 운영 브라우저 프록시 인증서 문제 역시 해결됐다고 주장하지 않는다. 관리자·공부 기록·통계는 후속이다.
