# 023. 기록 입력·월별 내 기록 화면 연결

Issue #48에서 로그인 후 기존 프로필 화면 아래에 월별 내 기록과 공부 기록 입력 팝업을 연결한다. 기존 Button·PeriodPicker·StudyDialog와 인증 JSON 전송·알림·입력 검증을 재사용한다. 기록용 CSS는 별도 CSS Module에 둔다. 달력·통계·수정/삭제·관리자 화면은 후속이다.

## 갱신과 데이터 보호

- TanStack Query5.105.0을 고정하고 로그인 사용자·그룹별 메모리 QueryClient를 사용한다. 기록 키에는 사용자·그룹·개인 범위·월을 포함한다. 세션·PIN은 Query나 웹 스토리지에 저장하지 않는다. 기록 화면이 해제되면 캐시를 비운다.
- 월 목록은 API의 커서에 따라 더 보기로 이어 읽는다. 월 변경 시 이전 월 데이터를 대체 표시하지 않는다. 추가 조회 실패는 기존 목록을 유지하며 재시도한다. 포커스·재연결·수동 갱신과 저장 성공 후 목록을 다시 읽는다. 서울 날짜는 화면 복귀와1분 주기로 확인한다.
- 생성 ID는 첫 제출에서 만들고 정규화한 입력과 함께 메모리에 유지한다. 네트워크/서버 오류로 결과가 불확실하면 입력을 고정하고 같은 ID·입력만 재시도하거나 GET id로 확인한다. 같은 요청을 자동으로 새 ID로 바꿔 중복 생성하지 않는다. 확정된 입력 오류 뒤 내용을 변경하면 새 ID를 사용한다.
- 저장 중 버튼·입력·닫기/Escape를 차단하며 중복 제출은 ref 잠금으로 막는다. 초안을 닫을 때 기존 버리기 확인창을 사용한다. 세션 만료 시 입력과 재로그인 링크를 유지한다.
- 다른 창에서 계정이 바뀐 경우를 위해 UI는 생성 요청에 expectedUserId를 보낸다. 서버는 실제 세션 사용자와 다르면 DB 저장 전에409 ACCOUNT_CHANGED로 거부한다. 쿠키를 제거하거나 다른 계정으로 저장하지 않는다. 월 조회의 응답 소유자·그룹도 현재 화면의 주체와 대조한다.

## 공부 종류

GET `/api/categories`를 기존 정상 일반 사용자 세션에 연결한다. 목록은 등록 순이며 비어 있거나 조회에 실패하면 저장을 막는다. 데이터가 많아도 DB 응답 제한으로 잘리지 않게 이어 읽는다. 제한 PIN 세션은403이다. 관리자 세션 허용은 관리자 인증 단계에서 추가한다. 운영 DB 스키마 변경은 없다.

## 검증

로컬 코드 검사와 단위 검사를 수행하고 CI에서 PostgreSQL/PostgREST 통합 및 실제 Chromium 입력 흐름을 확인한다. 브라우저 검사는 테스트 응답을 사용하며 운영 사용자 기록을 수정하지 않는다. SE3·패드·PC의 입력·목록·시스템 다크 설정의 밝은 테마 화면을 캡처한다. 최신 실행 결과와 미검증 항목은 PR에 갱신한다. 실제 iPhone Safari와 운영 계정의 화면 저장은 별도 검증이다.

로컬 최초 빌드는 Turbopack 생성 캐시의 SST 복원 오류로 실패했다. 기존 생성 캐시를 별도 임시 경로로 이동하고 새 빌드로 재검증한다. 해당 실패를 통과 결과로 취급하지 않으며 최종 결과는 PR에 기록한다.


첫 CI에서 DB 통합은 통과했고 브라우저69개가 통과했으나 입력 관련9개가 label 기반 선택란 식별에서 시간 초과됐다. 실패 시점 접근성 스냅샷의 정상 combobox를 확인해 실제 역할/이름을 사용하는 검사로 보완했다. 시스템 다크 설정에서도 현재 밝은 테마를 유지하는 것은 명세551행의 MVP 테마 정책을 따른다.
