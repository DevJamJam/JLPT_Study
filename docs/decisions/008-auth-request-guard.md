# 008. 인증 API 요청 검사 기반

연결 중단 이후 GitHub를 확인했다. PR #18과 Issue #17은 완료되어 main의
4b39878에 반영되어 있었다. 이전 로컬 복사본은 첫 커밋에 머물러 있으므로
그 파일을 덮어쓰지 않고 최신 main을 별도로 가져왔다. 완료된 인증 구현은 반복하지 않는다.

이번에는 Issue #19로 상태 변경 요청 검사만 구현한다. 서버 전용 인증 진입점에서
readMutationJson을 제공하며 POST/PATCH/DELETE, APP_ORIGIN과 정확히 일치하는 Origin,
application/json을 검사한다. APP_ORIGIN은 경로 없는 HTTP/HTTPS origin이어야 한다.

인증 입력은 작으므로 본문 상한을 4096바이트로 정했다. 이는 기존 명세에 없던 구현
기본값이다. Content-Length가 없어도 실제 스트림 바이트로 제한한다. UTF-8을 엄격히
해석하고 JSON 객체만 반환한다. 오류에는 상태와 고정 코드만 포함하며 원문·PIN을 넣지 않는다.
상한 초과 시 읽기를 취소한다. 필드별 검증은 기존 가입/로그인 검증 계층의 책임이다.

검증: 기존 15개와 추가 3개 단위 테스트 통과. 최초 타입 검사에서 테스트 헤더 배열 추론
오류를 발견해 명시적인 Record 타입으로 수정했다. 수정 후 포맷·린트·타입 검사와
단위 테스트 18개 및 운영 빌드가 모두 통과했다.
테스트는 정확한 Origin, 허용 메서드, 미디어 타입, 4096바이트 경계, 헤더 누락/거짓 길이,
Unicode 바이트 크기, 깨진 JSON/배열/null과 민감한 오류 내용 방지를 확인한다.

공개 API나 화면에는 아직 연결하지 않았다. DB 시도 예약/완료, 신뢰 가능한 IP 출처,
실제 Supabase와 인증 API/UI 연결은 미완료다. 인증 응답 no-store 설정도 API 단계에서 적용한다.
화면 변경이 없어 새 화면 캡처는 없다.
