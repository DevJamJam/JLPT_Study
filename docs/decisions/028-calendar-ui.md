# 028 — 실제 달력·날짜 상세와 공통 메뉴

## 변경

기존 /preview 시안은 가상 기록이었다. /calendar에 그룹 월간·내 월간·내 주간을 연결하고
/me에서 기존 월별 목록을 제공한다. SessionHome의 인증·설정·PIN·로그아웃을 유지한 채
공통 StudyShell을 사용한다. 미구현 스터디 통계 메뉴는 비활성화하며 홈/개인 통계는 후속이다.
기존 시안 CSS를 src/styles/notebook.module.css로 이동해 시안과 실제 달력이 함께 사용한다.
가상 데이터/시안 로직은 실제 화면에서 import하지 않는다.

- 서울 날짜, 월요일 시작,42칸, 내 주간7일. 모바일3명+N, 패드/PC11명+N.
- 월간은 calendar/members 조회, 주간·날짜 상세는 기존 기간 records 조회를 사용한다.
- 같은 그룹 공개 기록은 가입순 회원별로 묶고 시각/생성 마이크로초/ID 정렬을 유지한다.
- 본인만 수정·삭제한다. 기존 RecordForm/RecordDelete의 입력 유지·같은 ID/version 재시도와
  충돌 안내를 재사용한다. 상세·입력·삭제는 한 개의 native dialog를 교체해 중첩하지 않는다.
- 선택 날짜 추가, 하단+는 서울 오늘. 미래 상세는 읽을 수 있지만 추가는 막는다.
- 상세 출발 성공은 변경된 날짜 상세로 복귀, 직접+ 성공은 팝업 닫기. 기록/달력/멤버 Query를
  취소·무효화한다. 토스트는 입력·삭제 팝업 해제 후 표시한다.
- URL에 view/month/week와 date/scope/panel/recordId를 보관한다. 직접+는 direct=1이다.
  최초 팝업 push, 내부 전환 replace, 직접 URL 닫기는 팝업 조건만 제거한다.
- 잘못된 날짜·기간·ID는 정리한다. 브라우저 뒤로가기에서 초안/제출 보호가 필요하면
  popstate capture에서 현재 URL을 복원하고 기존 폼의 동일 close 확인을 거친다.
  취소는 초안을 유지, 승인 후에는 보호를 한 번 통과시켜 원래 history 이동을 수행한다.
- 배경 클릭·Escape·닫기/취소는 같은 close 경로다. 제출 중에는 이탈하지 않는다.
- 편집 초기 조회는 창 포커스/재접속으로 폼을 교체하지 않는다. 초안과 원래 version을
  유지하고 충돌 시 사용자가 명시적으로 최신값을 불러온다. 종료하면 편집 조회 캐시는 정리한다.
- 읽기 실패는0/빈 기록으로 위장하지 않고 재시도를 제공한다. 같은 기간 갱신 실패는 기존값을
  유지하며 세션·계정 오류는 이전 데이터를 숨긴다. 사용자별 Query 캐시는 메모리만 사용한다.

## 공휴일 상태

공식 공휴일 API/캐시는 후속 운영 작업이다. 시안의 세 날짜를 운영 공휴일 전체로 복사하지 않는다.
현재 화면에 공휴일 미확인 안내를 표시하고 토/일 색상만 적용한다. 공휴일 완료라고 보고하지 않는다.
