# 005. 공부 기록 검증과 서울 날짜 처리

## 문제와 선택

화면과 API가 서로 다른 기준으로 기록을 받으면 같은 입력이 한쪽에서는 통과하고 다른 쪽에서는 실패할 수 있다. 공통 순수 함수부터 구현하고 실제 저장 연결은 다음 단계로 남긴다. 날짜는 실행 기기의 시간대와 무관하게 Asia/Seoul을 사용한다.

## 구현 기준

- 공부 날짜: 실제 존재하는 YYYY-MM-DD, 2000-01-01부터 한국 기준 오늘까지.
- 공부 종류: UUID 형식. 등록된 종류인지는 서버에서 DB를 조회해 확인한다.
- 시간: 정수 1~1440분. 시작 시각은 생략 가능하며 입력하면 HH:mm 형식이다.
- 공부량: 정수 1~99999와 개·쪽·문제 단위를 함께 입력하거나 둘 다 생략한다.
- 메모: 앞뒤 공백 제거 후 Unicode 코드포인트 500개까지. 빈 메모는 null이다. HTML처럼 생긴 문장도 글자로 보관하고, 추후 화면에서 일반 텍스트로 출력한다.
- 검증 결과에는 허용된 기록 필드만 반환한다. 소유자와 권한을 결정하는 함수는 아니다.
- 하루 합계는 1440분까지다. 같은 날짜 수정은 기존 시간을 빼고 새 시간을 더한다. 다른 날짜로 옮기면 새 날짜 합계에서 기존 시간을 빼지 않는다.

## 검증

기존 Playwright 테스트 러너를 브라우저 없이 사용한다. 새 테스트 패키지를 추가하지 않는다. 10개 테스트로 한국 자정·연도 경계·윤년·미래 날짜·선택 항목·잘못된 숫자·공부량 조합·이모지 메모·일일 합산 경계를 검사한다. 포맷·린트·타입 검사와 운영 빌드도 통과했다. CI에 단위 검사 단계를 추가해 기존 화면 검사와 함께 실행한다.

## 남은 연결과 한계

현재 함수는 입력 화면이나 API에 연결되지 않았다. DB·인증·소유권 검사·실제 공부 종류 확인은 구현 전이다. 일일 합계 함수는 계산만 담당한다. 동시에 저장하는 요청의 상한은 서버 트랜잭션과 잠금으로 보장해야 하며 클라이언트 계산을 신뢰하지 않는다. 화면 변경이 없으므로 별도 디자인 캡처나 블로그 HTML을 생성하지 않는다.
