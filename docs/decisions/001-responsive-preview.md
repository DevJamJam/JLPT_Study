# 공통 디자인 구현 기준

- 운영 인증·저장과 분리한 /preview 경로에서 가상 데이터로 화면을 검토한다. 기능 구현 후 운영 경로에 공통 UI를 재사용한다.
- CSS Modules와 확정 CSS 변수로 스타일을 분리한다. Tailwind는 도입하지 않는다.
- 모든 기기에서 동일한 흰 헤더64px, 링30px, 제목176px와 하단 메뉴를 사용한다.
- 월간42칸·주간1/2/7열, 작은 화면3명+N·큰 화면11명+N을 적용한다.
- 날짜 상세와 기록 입력은 단일 native dialog의 내용 전환이다. 확인창은 native dialog를 닫고 SweetAlert2로 교체한다. 취소하면 입력 내용을 보존한 dialog로 돌아온다.
- 닫기·Escape·날짜 상세로 돌아가기에 작성 취소 확인을 적용한다. 모서리를 보존하는 바깥 overflow:hidden과 본문 overflow:auto를 분리한다.
- Chromium 375×667 / 820×1180 / 1280×900 검사와 캡처를 사용한다. 실제 SE3 Safari 검증을 대체하지 않는다.
- 공휴일은 가상 예시 세 날짜만 존재한다. 공식 서버 API 연동은 다음 단계다.
- 사용자 승인: HTML 전달 후 최종 PR 검토와 필수 검사가 통과하고 특이사항이 없으면 병합한다. 특이사항은 사용자에게 먼저 알린다.
