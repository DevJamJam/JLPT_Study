# 관리자 로그인과 공부방 관리

## 범위와 기준

생성된 ADMIN 계정을 별도 관리자 로그인에서 사용한다. 관리자 메뉴는 공부 종류·사용자 관리·
로그아웃이며 일반 공부 화면에 관리 메뉴를 넣지 않는다. 관리자 정원과 일반 회원 15명을 분리한다.
계정의 기존 비밀번호·해시를 변경하지 않는다.

## 인증과 데이터

- 초기화 명령과 동일한 고정 scrypt 파라미터로 비밀번호를 검증한다. 없는 계정도 동일한 연산을 수행한다.
- 기존 원자적 인증 시도 예약/완료 RPC를 admin_login namespace와 공유 출처 제한으로 재사용한다.
- 관리자 쿠키와 일반 쿠키를 분리한다. HttpOnly/Secure/SameSite=Lax와 고정 8시간 DB 만료를 적용한다.
- 서버 키는 기존 서버 전송에서만 사용한다. Origin·JSON·요청 크기 검사와 no-store 응답을 재사용한다.
- 새 DB 함수는 security invoker, 빈 search_path, public/anon/authenticated 실행권 회수 및 service_role 전용이다.
  관리자 세션은 각 변경 트랜잭션에서 다시 검사하며 만료·버전·폐기 상태를 반영한다.
- ADMIN은 대소문자·앞뒤 공백을 정리한 일반 가입에서 예약어로 차단하고 DB 제약도 추가한다.

## 관리 동작

공부 종류는 UUID 재전송, 이름 NFC·trim·1~20자, 비교 키 중복, 생성 순서 잠금을 처리한다.
수정·삭제는 화면에서 읽은 이름과 비교해 오래된 요청이 새 이름을 덮어쓰지 않게 한다.
참조 중인 종류 삭제는 CATEGORY_IN_USE로 거부하며 기존 기록은 유지한다.

팀원 목록은 공개 프로필·가입일·자격증명 버전만 반환한다. 내보내기는 그룹→멤버→자격증명
잠금 후 계정을 삭제해 FK cascade로 기록·세션·요청 이력까지 원자적으로 제거한다.
없는 UUID 삭제 재시도는 성공이며 오래된 자격증명 버전 요청은 충돌로 거부한다.

PIN 초기화는 서버에서 0000을 기존 pepper 방식으로 해시하고 요청 UUID·actor/target/version의
HMAC 지문을 기록한다. 같은 요청 재시도는 새 해시를 덮어쓰거나 버전을 다시 올리지 않는다.
모든 사용자 세션을 폐기하고 must_change_pin·버전을 갱신한다. 기존 강제 변경 화면을 재사용한다.
초기화 당시 미완료 인증 시도와 닉네임 잠금도 정리하되 출처 제한을 해제하지 않는다.

확인창은 기존 SweetAlert2 공통 함수를 재사용하고 취소에 최초 포커스를 둔다. 회원 내보내기는
계정·기록 영구 삭제와 복구 불가를 명시한다. 실패는 행/입력을 유지하며 초기화 재시도 ID도 유지한다.
관리 API는 일반 세션을 403, 일반 공부 API는 관리자 전용 세션을 403으로 거부한다.

## 검증 및 운영 적용

로컬 정적 검사·빌드와 단위 104개 + 초기화 명령 5개가 통과했다. UI 검사와 DB 계약 검사는
CI에서 실행하며 결과·화면 캡처·실제 운영 적용 상태는 PR에 계속 갱신한다.
화면 검사는 가상 데이터이고 실제 관리자 로그인이나 실제 회원 삭제를 의미하지 않는다.
실제 관리자 로그인은 사용자의 비공개 인증 입력 후 확인해야 한다.

Supabase CLI가 이 환경에 없고 npx 조회가 25초 제한에서 종료되어, 이 저장소의 기존 날짜/순번
파일 규칙으로 SQL을 작성했다. 운영 변경 전 격리 DB 계약 검사와 권한 검토를 완료한다.
새 테이블/컬럼 또는 관리자 자격증명을 추가·변경하지 않으며 기존 데이터의 일괄 삭제도 하지 않는다.
Supabase changelog의 새 API 테이블 노출 기본값·TLS 변경을 확인했다. 기존 service_role 테이블
권한을 유지하고 함수 실행권만 한정한다. 함수·권한 공식 문서를 확인했다.

후속 순서와 실제 운영 검증은 Issue #64, 구현·배포는 Issue #68에서 추적한다.
