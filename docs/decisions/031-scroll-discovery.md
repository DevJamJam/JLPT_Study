# 스크롤 발견 가능성과 운영 검증 구분

## 문제와 원인

PR #63은 본문과 하단 메뉴를 분리했지만, 운영체제가 자동으로 숨길 수 있는 얇은 기본 스크롤바에 의존했다. 화면만 보고 아래에 내용이 남았는지 알 수 없다는 사용자 피드백을 수용한다. 이전 모의 API 캡처를 운영 계정 검증으로 표현해서도 안 된다.

## 변경

- 공통 하단 영역에 실제 본문이 넘칠 때만 안내, 현재 위치 막대와 44px 위·아래 이동 버튼을 표시한다.
- 처음에는 위 버튼, 끝에서는 아래 버튼을 비활성화하고 끝 도달 안내를 표시한다. 버튼은 키보드로도 작동한다.
- 스크롤·본문 변경·창 크기 변경을 관찰한다. 본문과 안내 및 메뉴의 영역은 분리하고 올라온 기록 버튼의 공간도 확보한다.
- 기본 스크롤바의 폭과 대비도 높인다. 동작에 애니메이션을 강제하지 않는다.

## 검증 상태

- 로컬 정적 검사와 단위 검사 101개 통과. 운영 빌드와 CI 브라우저 검사는 진행 중이며 완료 결과는 PR에 갱신한다.
- 브라우저 검사는 모의 API 데이터로 스터디·달력·내 기록의 처음/중간/끝, 마지막 항목 접근, 팝업 복귀, 스크롤 버튼과 위치 표시, 짧은 본문 및 높이 변경을 검사한다.
- 운영 DB 읽기 조회 결과 회원 0명, 제안한 테스트 닉네임 중복 없음. 운영 로그인 화면 접근 확인.
- 운영 계정 생성과 로그인·실제 기록 저장은 아직 미완료다. 연결된 브라우저의 인증 지침상 신규 계정 가입 및 PIN 입력은 사용자 인계가 필요하다. 계정이 존재하거나 운영 저장을 검증했다고 주장하지 않는다. 자격 증명은 저장소와 PR에 기록하지 않는다.
- 실제 iPhone Safari 검사는 수행하지 않았다. CI의 SE3/iPad/PC 이름은 Chromium 화면 크기를 뜻한다.
