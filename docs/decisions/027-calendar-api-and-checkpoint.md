주석을 명확히 한다. README의 현재/예정 경로·검사 도구와 미완료 설명도 실제 코드에 맞춘다.

## API와 권한

- GET /api/members: 검증된 일반 사용자 세션의 같은 그룹만 가입순(joined_at, user_id)으로 읽는다.
  공개 필드는 id/nickname/emoji/joinedAt이며 자격증명·세션·공부 기록은 읽지 않는다.
- GET /api/calendar?scope=mine|group&from=YYYY-MM-DD&to=YYYY-MM-DD:
  기존 기간 검증을 재사용하고 양 끝 포함 최대42일이다. month/cursor·중복/임의 파라미터는 거부한다.
- 기존 기록 HTTP 계층의 세션·정상 PIN 상태·no-store·오류 정제·시간 지표를 재사용한다.
  별도 인증 guard를 복제하지 않는다. 그룹·본인 조건은 세션으로 고정한다.
- 달력은 id/group_id/user_id/study_date/minutes만 서버에서 조회한다. 메모나 종류·fingerprint는
  필요하지 않아 읽지 않는다. 응답은 날짜/합계/참여자별 시간만 제공한다.
- 빈 날짜도 합계0·참여자[]로 반환한다. 한 사람의 여러 건은 합산해 참여자1개로 표시하며 가입순 유지.
- DB row cap이 작아도 빈 페이지까지 읽는다. 기록은 ID keyset을 사용해 순서가 진행하지 않는
  응답을 거부한다. 잘못된 그룹/멤버/날짜/숫자 DTO를0으로 대체하지 않는다.
- 스키마·RLS·공개 브라우저 권한은 변경하지 않는다. 서버 REST 비밀값은 기존 방식 그대로다.

## 검증과 한계

신규 단위6개로 빈 날짜·윤일·연말·9999년 상한·가입순·여러 기록 합산·작은 row cap·권한·입력·
잘못된 DTO를 검사한다. 기존 단위87개와 합계93개다. 실제 DB 통합은 기존5개에 멤버/달력
검사를 추가해6개이며501건 cap100, 개인/그룹 구분, 타 그룹 제외, 이모지 갱신,42일 상한을 확인한다.
최종 CI 결과는 PR에 기록한다. 기존 브라우저96개도 회귀 검사한다.

여러 REST 요청은 하나의 DB 스냅샷이 아니다. 요청 중 생성·수정·삭제·회원 변경이 겹치면
다음 조회에서 수렴하며, 회원 데이터와 맞지 않는 행은503으로 닫는다. 새로운 집계 테이블은 없다.
공휴일·달력 셀·날짜 상세·공통 메뉴는 다음 화면 작업 범위다. 이번 PR은 UI 변화가 없어 새 캡처가 없다.
