003 · 읽기 쉬운 HTML과 프로젝트 안내

이슈 #1 · docs: 문서 포맷과 README 구조 정리

문제

시안을 한 줄로 저장하면 요소 경계를 찾기 어렵고 Git 변경 사항도 읽기 힘들다. 기존 README는 실행 가능 여부와 폴더 역할 설명이 부족했다.

변경 이유

HTML 태그·CSS 규칙·스크립트에 줄바꿈과 두 칸 들여쓰기를 적용했다. 이는 원본을 압축하는 배포 작업과 별개다. README는 현재 상태와 구현 계획을 구분하고 아직 없는 npm 명령을 실행 가능하다고 안내하지 않는다.

폴더 구조 결정

기존 app/features/components/lib 기준을 유지한다. app은 경로, features는 기능별 작업, components는 공통 화면 요소, lib는 공통 함수다. 자체 인증과 DB 코드를 server에 모아 클라이언트와 구분하고 공통 색상은 styles에서 관리한다. 한 기능에서만 쓰는 코드를 공통 폴더로 옮기지 않는다.

포맷 기준

.editorconfig에 indent_size=2를, .prettierrc.json에 tabWidth=2를 저장했다. 설정 파일은 기준이며 포맷터 설치나 CI 자동 실행이 구성됐다는 뜻은 아니다.

검증

포맷 전후 DOM 요소와 속성, 스크립트 토큰과 CSS 내용을 비교한다. HTML 파싱·목차·README 링크·YAML/JSON 파싱·스크립트 문법도 확인한다. 실행 결과는 PR 검증 내역에 적는다. 실제 브라우저·DB·앱 빌드는 아직 미실행이다.
